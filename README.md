# Тестовое задание Сенная Стор

## План
- Создаём простой TypeScript проект. Берём Vitest для тестов.
- Пишем минималистичный вариант функции под требования.
- Разделяем ноутбук и историю, показываем запись через асинхронные заглушки.
- Покрываем тестами.

## Запуск

Нужен Node.js 22.12+.

```sh
npm ci
npm test
npm run typecheck
```

`await changeStatus(laptop, nextStatus, history, now?)` в `src/change-status.ts`
возвращает `{ ok: true, laptop, historyEntry }` или `{ ok: false, error }`.
Входные данные не изменяются. История передаётся отдельно, от старых записей к новым;
записи связаны с ноутбуком через `laptopUuid`.
Модель: `{ uuid: crypto.randomUUID(), status: Status.IN_STOCK }`;
enum `Status` находится в `src/models.ts` (`IN_STOCK`, `RESERVED`, `SOLD`, `WRITTEN_OFF`).

`updateLaptop` и `addHistoryEntry` в `src/persistence.ts` — async-заглушки без хранения.
При подключении БД обе записи нужно объединить транзакцией; ошибки записи отклоняют Promise.

## Что было непонятно и как решили

14 дней — ровно 14 × 24 часа с последней продажи, граница включена.
Дату продажи берём из истории; при повторной продаже срок начинается заново.
Даты истории записываются в UTC (ISO 8601). Возврат без корректной даты продажи
или раньше продажи запрещён, переход в тот же статус — ошибка.
